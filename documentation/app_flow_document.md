# Company Dashboard System - App Flow Document

## Onboarding and Sign-In/Sign-Up
A new user lands on the public landing page of the Company Dashboard System. From there, they can click a Sign Up button which opens a modal or dedicated page where they choose between entering an email and password or using a social login option such as Google. When signing up with email, the user fills in their name, email, and a password, and then receives a confirmation link by email via Supabase Auth. When the link is clicked, the account is activated and the user is directed to the appropriate dashboard. If they choose social login, they approve access through the provider and are immediately logged in.

To sign in, returning users click the Sign In link, enter their email or social login provider, and are redirected to their dashboard based on their role. A prominent Forgot Password link on the sign-in page allows users to request a password reset email. The user clicks the link in the email, enters a new password, and is taken back to the sign-in page. A Log Out button is visible in the header of every authenticated page, which signs the user out and returns them to the public landing page.

## Main Dashboard or Home Page
After signing in, viewers and administrators are routed to different default home pages under the Next.js route groups. Viewers land on the Display Portal home, which features a three-column layout showing news items, urgent tasks, and employee status bars side by side. A top navigation bar allows quick access to a user profile page and a log-out button. Administrators land on the Admin Dashboard home, which shows a sidebar navigation linking to each management section (Todos, News, Employees, Urgent Tasks, Photos, Attendance). The main area of the Admin Dashboard home displays summary cards that show counts or recent items in each module.

Both portals share a consistent header with a logo on the left and a user avatar on the right. Hovering or clicking the avatar reveals a dropdown with links to Profile Settings and Sign Out. The sidebar in the Admin Dashboard can be collapsed to increase horizontal space for forms and tables.

## Detailed Feature Flows and Page Transitions

When a viewer opens the Display Portal, the page is rendered on the server using Next.js Server Components to fetch the latest data from Supabase via Drizzle ORM. As soon as the component mounts on the client, a custom `useRealtimeSubscription` hook opens a Supabase Realtime channel for each table and listens for INSERT, UPDATE, or DELETE events. When an event arrives, the component state updates and React re-renders the affected column. If the real-time connection drops, the page shows a small banner that data is unavailable and then resumes updates when the connection is restored. In addition, a hidden client timer triggers a full page refresh every 60 seconds as a fallback.

In the Admin Dashboard, an administrator clicks the sidebar link for Todos and sees a table of existing tasks fetched by a Server Component. To add or edit a task, they click an Add Task or Edit icon which loads a form component. The form fields use shadcn/ui Input and Select components. Submitting the form calls a Next.js Server Action that validates the data, then uses the Supabase client to write to the `todos` table. After the server action completes, it calls `revalidatePath('/admin/todos')` to update any cached page and the component redirects back to the table view automatically. Simultaneously, the write triggers a Realtime event that pushes to all viewers and other admins.

Administrators navigate between modules by clicking sidebar links. Each link uses Next.js’ built-in Link component so transitions are instant without a full reload. When switching to the News section, a new Server Component runs to fetch news items. When editing employees or attendance, the pages follow the same pattern of showing a table, opening a form, submitting through a Server Action, and revalidating caches.

## Settings and Account Management
Every user can access Profile Settings by clicking their avatar and selecting Settings. On the Profile Settings page, users see a form with fields for name, email, and password. Changing the password triggers a secure request through Supabase Auth and requires entering the current password for security. Users can also set notification preferences for email alerts, which are saved in a `profiles` table via a Server Action.

Administrators have no separate billing or subscription pages in this system. Once profile preferences are saved, the user is automatically redirected back to their respective dashboard home. A success message confirms that settings are updated.

## Error States and Alternate Paths
If a user enters invalid credentials on sign in, an inline error message appears above the form guiding them to retry or reset their password. During sign up, if the email is already in use, an error informs the user and suggests they sign in or reset their password. When filling forms in the Admin Dashboard, field-level validation messages display next to the offending input if required fields are missing or data formats are invalid.

If the Supabase Realtime connection fails in the Display Portal, a non-blocking banner states “Realtime updates temporarily unavailable” and the page attempts to reconnect every few seconds. During this time the fallback 60-second refresh ensures data stays reasonably current. If a user tries to manually navigate to an admin route without proper authorization, Next.js middleware redirects them to the sign-in page. For any unknown URL, both portals show a custom 404 page with a brief message and a link back to the dashboard home.

## Conclusion and Overall App Journey
A new user begins at the public landing page and signs up with email or a social provider. After confirming their account, they sign in and land on either the Display Portal or the Admin Dashboard depending on their role. Viewers enjoy a live three-column view of news, tasks, and employee statuses that update instantly or every minute. Administrators use a collapsible sidebar to access and edit each module through tables and forms that submit via Server Actions. Both roles can update their profile settings and sign out. Across every page, the combination of server-side rendering, client-side subscriptions, and cache revalidation keeps data fresh, secure, and responsive to real-time changes.
